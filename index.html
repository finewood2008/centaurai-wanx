Wanxiang / Product specification Draft 0.1
社群陪跑的工作 Agent Builder

万象

在同一个万象工作台里，引导普通人把真实工作流程构建成可连接数据、可验证、可审计、可持续改进的 Agent；社群在流程外提供咨询与反馈。

状态　待共同评审
日期　2026-08-30
Owner　万象团队
形态　本地单体应用
01 / Problem

问题不是生成太难，而是交付真实价值太难。

一句话生成隐藏了需求澄清、数据理解、异常处理、权限、安全和验收等必要工作。普通人独自完成这些工作并不现实，因此大量“应用”只在演示时成立。

万象把成员的领域判断与 Builder Agent 的构建能力组成交付系统，目标是完成真实工作，而不是降低第一次生成的摩擦。社群是独立支持服务，不承担流程审批。

“用户不是在万象里做出一个应用，而是让一项真实工作第一次被可靠地完成，并能在此后重复运行。”
Goals

我们要证明

  • 社群陪跑能稳定交付有用的工作 Agent。
  • 成员能参与验收并逐步获得维护能力。
  • 需求发现、Builder Agent 和 Data Agent 能形成完整闭环。
  • 自动化范围可以随真实证据逐步扩大。
Non-goals

我们暂时不做

  • 不承诺“一句话生成任意应用”。
  • 不先建设拖拽编辑器或大型模板市场。
  • 不另起一套引导产品，也不让用户在多个界面间跳转。
  • 不以页面数量、创建量或演示效果衡量价值。
02 / Core loop

从真实案例到持续运行

01

发现

带来最近真实发生过的任务，明确输入、步骤与完成标准。

02

定义

确认工作流、数据契约、异常、权限和风险边界。

03

构建验证

在万象原生工作台里组合能力，同时运行案例、查看证据并修正。

04

使用

在同一个万象工作会话中运行、批准、回归验证和持续改进。

03 / Architecture

万象是一套连续、开放的 Agent 工作台

社群成员

提供领域判断、验收证据与高风险批准。

→

万象工作台

把需求发现、构建验证、运行、批准和教学组织在同一个界面中。

→

Data Agent Bridge

按最小权限提供真实数据能力，并返回来源与可追踪结果。

05 / User stories

产品角色与外部支持

作为社群成员

我希望从一项真实任务开始，在每一步知道系统需要我判断什么，从而得到自己能使用和维护的 Agent。

作为社群支持者

我希望通过独立服务回应咨询、收集反馈和组织课程，但不介入成员的流程解锁、验收与发布判断。

作为平台运营者

我希望复用课程、策略和能力，同时固定运行时与能力版本，从而稳定扩大交付规模。

06 / MVP scope

先完成一条垂直切片

人群：10–20 名成员，聚焦 1–2 类相邻工作场景。

任务：每人一个高频、低到中风险、结果可判断的工作流。

能力：万象本地运行时、Builder Agent、只读 Data Agent Bridge、案例评测、影子运行、人工批准和版本回滚。

完成门槛：不少于 5 个案例、至少 2 个边界案例、3 次真实运行、所有高风险动作受控、成员能够完成一次小修改。
