已经像一个产品，而不是框架上的引导层

最明显的进步是“一个万象”的整体感：真实工作从原生输入框开始，工作说明只作为同一对话的动态契约出现，确认后仍在原位制作。暖纸、玉绿和编辑式回答建立了可信、低压的气质，安全状态也没有被视觉包装掩盖。

8.6

哲学

Strong
  • 首屏直接问“今天想把哪件真实工作交给万象？”，把价值锚定在真实、重复发生的工作，而不是生成应用。
  • 工作说明明确区分用户确认、根据案例推断和待确认；“完成”必须由真实材料与验收证据支撑。
  • 社群抽屉诚实说明“仅保存在本机，尚未发送”，没有把外部服务伪装成产品能力。
KEEP

继续让证据、边界与用户判断先于完成动画。

FIX

旧历史回答仍偶尔以“代码已完成”开场；未来应让验收摘要先于实现清单。

QUICK WIN

在完成态固定展示“真实输入 / 验收证据 / 用户接受”三联摘要。

8.2

视觉层级

Strong
  • 新项目首屏只有一个主问题、三个真实工作示例和一个原生输入框，视线顺序清楚。
  • 低密度侧栏、宋体标题、暖纸背景与单一玉绿动作色形成稳定的品牌层级。
  • 400px 桌面抽屉不遮罩主界面；900px 进入 420px 模态；600px 近全宽，断点行为符合阅读任务。
KEEP

保留“标题开放、操作克制、证据可折叠”的编辑式构图。

FIX

超长历史回答在中屏仍会与抽屉争夺注意力，缺少更强的阶段性导航。

QUICK WIN

为长回答增加小型段落目录，仅在超过三个二级标题时出现。

8.4

细节

Strong
  • 浅色与深色分别使用完整的纸面、卡片、正文、玉绿和分隔线 token，不是简单反色。
  • 抽屉支持 Escape、焦点圈定、关闭后焦点恢复；600px 下没有横向溢出。
  • 页面标题、运行记录、工作规则和权限状态都已转成万象语言，模型提供方名称作为必要事实保留。
KEEP

继续使用 120–180ms 的轻动效，并尊重 reduced-motion。

FIX

模型推理等级与少量运行指标来自供应方元数据，仍偏技术化。

QUICK WIN

为已知推理等级和运行统计增加产品化显示名，同时保留原值在详情中。

8.8

功能

Strong
  • 对话、附件、模型选择、停止、队列、审批、工具生命周期和运行记录都留在原生会话中。
  • 七项工作说明有 CAS、字段来源、确认快照和多标签冲突处理；权威状态不在 Agent 可写工作区。
  • “开始制作”在同一会话执行幂等激活，切权限、刷新、校验和发送任一步失败都会关闭写工具并提供恢复路径。
KEEP

保持同一会话、单次激活和失败关闭写权限这三条硬约束。

FIX

Data Agent 与远端社群尚未连接，首发价值仍依赖本地材料和公开资料。

QUICK WIN

在首次运行证据卡中固定标注数据来源是本地、公开资料还是示例契约。

8.0

创新

Strong
  • 把工作说明做成模型持续更新、用户随时修正的动态契约，比固定六步表单更贴近真实协作。
  • 同一个 Agent 从理解进入制作，不切角色、不派发第二会话，显著降低“两个产品”的割裂感。
  • 创新集中在工作闭环与安全协议，而不是用全新的交互替换成熟的对话框架。
KEEP

继续把创新放在可验证工作能力，而不是生成速度或界面噱头。

FIX

工作说明目前仍以七张文本卡为主，案例证据与字段之间的关系可更直观。

QUICK WIN

允许从一条真实案例直接生成“规则—边界—验收”关联预览，用户逐项确认。

Keep

  • 单一原生对话与单一工作说明入口。
  • 暖纸 + 玉绿的低压可信气质。
  • 真实材料、验收证据与用户接受的完成门槛。

Fix

  • 降低长历史回答与运行指标的技术密度。
  • 让旧项目也稳定呈现真实权限，而非只根据项目阶段推测。
  • 连接 Data Agent 前持续明确能力边界。

Quick wins

  • 为长回答提供轻量目录。
  • 翻译已知推理等级与运行统计显示名。
  • 在结果卡固定标记数据来源和验收证据。

评审依据：本地真实进程、最终 DOM 与视觉截图；桌面 1118×783、平板 900×800、窄屏 600×800；浅色与深色主题；工作说明与社群抽屉；Escape、焦点恢复、冷启动和品牌术语扫描。分数代表当前 MVP 的设计成熟度，不代表尚未接入的 Data Agent 或远端社群能力已经完成。
