# 万象一体化运行架构 · Draft 0.2

## 架构决定

万象只有一个产品、一个本地进程、一个浏览器入口和一套持续工作流。需求发现不是外置引导程序，而是万象原生工作台中的一个主表面；确认工作简报后，界面原位进入自由构建与验证会话，用户可以随时返回修改需求。

底层 Agent 内核作为内部实现随项目精确锁定和安装，不作为用户需要理解、安装或操作的第二个产品。万象使用独立数据目录，不读取电脑中其他 Agent 工具的配置、插件或会话。

## 逻辑架构

```text
万象本地应用（localhost:3000）
├── 需求发现：六轮对话 + 实时工作简报
├── 构建验证：会话、模型、工具、文件与运行证据
├── Builder 策略：工作契约、安全边界与构建验证循环
├── Data Agent Bridge：受控的数据能力面
└── 社群抽屉：流程外的咨询与反馈服务
```

需求发现与构建验证共享同一个侧栏、工作区、会话系统和权限模型，不进行跨端口跳转。

## 运行时边界

- 根命令 `pnpm start` 启动唯一的万象工作台。
- 项目随包安装并精确锁定内部运行时版本，不依赖本机源码目录。
- `.wanxiang-runtime/engine` 保存万象自己的配置、凭据与会话索引。
- `.wanxiang-runtime/workspaces` 保存用户项目和生成产物。
- 产品配置关闭第三方默认品牌、插件清单、无关测试插件和第三方身份提示。
- 第三方许可保留在 `THIRD_PARTY_NOTICES.md`，但第三方产品身份不进入万象 UI 或模型人设。

## 工作区契约

每个工作 Agent 都有独立、可版本化的工作区：

```text
workspace/
├── AGENTS.md
└── .wanxiang/
    ├── work-brief.md
    ├── data-contract.json
    ├── workflow.json
    ├── evals.json
    ├── runs/
    └── releases/
```

工作区路径是项目身份的一部分。浏览器中的需求状态按工作区分区；工作区精确匹配失败时创建当前工作区，不允许退回或重命名其他项目。

## 工作简报一致性

工作简报包含真实任务、输入资料、判断规则、交付结果、边界风险和验收标准。用户确认时，万象先确认当前工作区没有仍在执行的任务，再通过同源受控接口原子写入 `.wanxiang/work-brief.md`，随后把新简报交给 Builder 会话；模型不负责替产品保存这份契约。

确认期间表单冻结，并使用简报修订号防止异步启动与用户新修改发生分叉。边界发生变化时，新修订进入同一个工作会话的队列；若当前任务仍在运行，万象会先阻止落盘并提示用户等待或停止任务，避免新旧 Agent 并发写入同一工作区。

## Builder Agent

第一版使用一个 Builder Agent，在同一个循环中完成：

1. 阅读已确认工作简报与数据契约。
2. 选择最小可用切片并实现。
3. 立即运行代表性案例与边界案例。
4. 根据证据修正，直到成员能够判断结果是否可用。
5. 对外写入、发送、删除和付款等动作始终先预览并获得明确批准。

系统提示词只使用万象身份和策略；运行时上下文、工具与权限机制继续保留。

## Data Agent Bridge

Data Agent Bridge 是万象访问业务数据的唯一能力面。模型只能看到经过裁剪的能力描述和结果，不能直接持有业务凭据。读取与写入分开授权；每个结果包含来源、时间、动作摘要和可追踪 ID。

当前 MVP 只有示例数据契约，因此不得声称已经连接真实数据，也不得执行外部写入。

## 社群服务

社群以侧边抽屉存在，可用于咨询问题和提交反馈。它不进入 Agent 流程，不解锁阶段，不替成员确认需求，也不决定验收结果。

## 安全与运营

- 默认只允许工作区写入，高风险动作需人工批准。
- 本地服务只绑定回环地址；工作简报写入接口校验同源请求、字段和大小。
- 会话、凭据和临时运行产物不进入 Git。
- 依赖版本、原生模块和第三方许可随发行包固定并验证。
- 版本升级必须通过语法、单元、启动、浏览器交互和完整项目回放。

## 第一条垂直切片

1. 成员从最近一次真实任务开始，完成六轮需求对话。
2. 万象原子保存确认后的工作简报。
3. 界面原位进入同一项目的构建验证会话。
4. Builder Agent 创建最小实现并运行至少 5 个案例，其中至少 2 个为边界案例。
5. 真实数据接入前只做示例或影子运行；达标后再逐步扩大自动化权限。
